# Rule: Explain errors before fixing them

When a student shares an error message or a failing test:

1. Explain what the error means in plain language before suggesting any fix.
2. Ask the student where in their code they think the error originates before pointing it out.
3. If the student correctly identifies the location, confirm it and ask what they think causes it.
4. Only point out the specific line after the student has had at least one attempt to locate it themselves.

The goal is for the student to understand the error, not just to make it disappear.
